# Проект "Магазин" (Clean Code & SOLID)

## Реализованный функционал:
- Каталог товаров (добавление, получение списка).
- Фильтрация товаров по цене (с возможностью расширения).
- Корзина пользователя (добавление, удаление, подсчет суммы).
- Оформление заказа и трекинг его статуса (с использованием Enum).
- Рекомендательная система (выдает до 3 товаров, которых нет в корзине пользователя).
- Возврат заказа.

## Применение принципов SOLID:

**1. Single Responsibility Principle (SRP)**
*Каждый класс отвечает только за одну задачу.*
- Класс `Cart` (в `com.shop.services.Cart`) отвечает исключительно за логику корзины (хранение товаров и подсчет суммы).
- Класс `DeliveryService` (в `com.shop.services.DeliveryService`) занимается только логикой доставки и изменения статуса заказа.

**2. Open/Closed Principle (OCP)**
*Классы открыты для расширения, но закрыты для модификации.*
- В пакете `com.shop.filter` создан интерфейс `ProductFilter`. Если нам понадобится фильтр по производителю, мы просто создадим новый класс `ManufacturerFilter implements ProductFilter`, не меняя существующий код фильтрации по цене.

**3. Liskov Substitution Principle (LSP)**
*Наследники могут заменять своих родителей.*
- В `Main` переменная объявлена как `ProductFilter cheapFilter = new PriceFilter(MAX_PRICE);`. Благодаря LSP, мы можем безболезненно заменить `PriceFilter` на любой другой класс, реализующий `ProductFilter`, и программа продолжит работать корректно.

**4. Interface Segregation Principle (ISP)**
*Интерфейсы не должны заставлять реализовывать лишние методы.*
- Интерфейс `ProductFilter` (в `com.shop.filter.ProductFilter`) содержит только один необходимый метод `filter()`. Классу `PriceFilter` не приходится реализовывать лишние методы, которые ему не нужны.

**5. Dependency Inversion Principle (DIP)**
*Зависимость на абстракциях, а не на конкретных реализациях.*
- В методе `main` класса `Main` мы работаем с абстракцией: `ProductFilter cheapFilter = new PriceFilter(...)`. Зависимость строится от интерфейса, а не от конкретного класса.

## Другие правила чистого кода:

**DRY (Don't Repeat Yourself)**
- В классе `Cart` метод `getTotalPrice()` использует Stream API для подсчета суммы в одну строку, избегая дублирования логики циклов.

**Избегание магических чисел**
- В классе `Main` вынесена константа `public static final double MAX_PRICE = 500;`. Вместо числа 500 прямо в коде, мы используем именованную константу.
- Статусы заказа вынесены в отдельный Enum `OrderStatus` (в `com.shop.models.OrderStatus`), что исключает использование "магических строк" вроде `"Shipped"` или `"Returned"`.

## Тестирование:
Проект покрыт Unit-тестами с использованием JUnit 5 (в папке `src/test/java/com/shop`):
- `CartTest` проверяет добавление, удаление и подсчет стоимости.
- `PriceFilterTest` проверяет корректность фильтрации товаров.
- `DeliveryServiceTest` проверяет изменение статусов заказа.
